# 星海公约：分步上线计划

更新：2026-10-20。先验证好不好玩，再处理平台移植；以下周期是开发安排估计，不是平台审核承诺。

## 建议顺序

**先跑通 2D 单机网页版 → 手机平台最小样片 → 3D 单场景验证 → 2–4 人合作 App → 再扩展大世界。**

人物主线、作品研究和各阶段验收详见 [世界设计与路线图](WORLD_ROADMAP.md)。iOS 的网页容器方案只用于复用 2D 版本进行技术验证，是否发行独立 2D App 可在试玩后决定；它不等于完成未来的 3D 多人版。微信与 iOS 的先后取决于目标玩家和准入条件。

当前是以剧情、选择和小游戏组成的游戏。微信“小程序”和“小游戏”是不同产品路径，不能只改一个名称就当作同一种上架方式。不要先花钱同时重写两端，也不要把“免费／只有广告”直接等同于不需要资质。

## 第一步：把现有版本做成可反复验证的试玩版

建议先用约 1–2 周邀请 10–20 位试玩者。六章和新增玩法已在仓库中，先重点观察第一章：玩家能否理解目标、找到证据、完成质证、看到裁决并愿意继续第二章。

- 维护仓库的 `index.html`、`css/`、`js/`，用 `tools/build.py` 生成本地单文件。不要再各自修改三份成品。
- 先验收桌面、iPhone Safari、安卓微信内置浏览器。电脑自动化不能替代这两种手机的真机检查。
- 检查音频解锁、刘海与底部安全区、横竖屏、切到后台再回来、导出导入和清理浏览器数据后的行为。
- 第一轮用一张反馈表即可，不急着加账号、云存档、支付、广告 SDK 或自动埋点。
- 首版上线前把“开发占位广告”关闭；当前 `MONETIZE.adsDemo` 仍是开发演示开关，并未接入真实广告。

进入下一步的条件：核心路径没有阻断问题；试玩者知道下一步做什么；手机运行和存档稳定；确认剧情与素材可发布。

网页版首次访问仍需网络。单文件离线版已经打包资源；网页本身还没有 Service Worker，不应宣传“网页首次加载后保证离线可玩”。

## 第二步：iPhone 内测，尽量复用网页

**建议评估 Capacitor。** 它可以在原生容器中运行现有 HTML/CSS/JavaScript，并接入系统能力，适合先验证这个项目；没有必要现在重写为 Swift 或重新做游戏引擎。[Capacitor 官方文档](https://capacitorjs.com/docs)

这一步的最小交付：

1. 用 Xcode 建立 iOS 工程，将游戏资源随 App 打包，离线可打开。
2. 处理安全区、横竖屏、切后台时暂停音频和游戏、来电后恢复。
3. 把存档接到可靠的 App 本地持久化，并接入系统文件分享／导入；不能直接假定浏览器下载按钮在 WKWebView 里也能正常工作。
4. 用真机验证第一章和一个小游戏，再上传 TestFlight。
5. 通过实际试玩决定是否投入正式上架材料和更多系统能力。

Apple Developer Program 当前标准年费为 99 美元，按账号所在地区显示的价格支付。先验证技术路线，再支付会员费用。[Apple 开发者注册](https://developer.apple.com/programs/enroll/)

TestFlight 用于测试，并不等于已经获准在 App Store 正式销售。正式提审仍需应用信息、截图、支持入口、隐私政策、年龄分级等。Apple 的 4.2 最低功能要求强调足够的实用性和体验；把网站装进容器不保证过审，应把离线体验、操作、系统分享和生命周期适配做完整。[App 审核指南](https://developer.apple.com/cn/app-store/review/guidelines/)

发布地区也要先选定。Apple 的中国大陆可用性说明列明游戏审批号与支持材料要求，并涉及适用的备案信息；不能因为游戏免费就假定不适用。选择其他地区也要符合当地规则和商店审核，不能承诺上线日期。[App Store Connect 应用信息](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information/)

## 第三步：微信先做技术小样，再决定投入

先在公众平台核对实际主体、服务类目、准入材料和可用能力。本轮未能直接读取微信开放文档页面，因此不把此前文档中关于个人主体、广告变现、包体上限和版号的具体说法当作已核实的当前规则。

有两条真正不同的产品路线：

| 目标 | 建议做法 | 先验证的最小版本 |
| --- | --- | --- |
| 保留星图、角色、法庭演出和小游戏 | 优先评估微信小游戏 | 第一章的一段对白、一道质证、结算与存档，加一个小游戏 |
| 做轻量法律互动学习产品 | 重新设计为适合普通小程序的卡片、问答和学习档案 | 一个案例、三次选择、一页解释；按实际内容申报类目 |

当前代码大量使用 DOM、SVG、CSS 和 Web Audio。**不能把现有 HTML 直接当作已经完成的小程序或小游戏。** 评估小游戏时，需要逐项验证界面绘制、触摸、音频、存档等适配；Canvas 星图和纯数据剧本可以作为复用起点，但同样要在实际运行环境中测试。

若采用小游戏路线，先做上述小样并检查低端安卓机的文字可读性、帧率与内存，再决定用 Canvas 适配层还是游戏引擎。不要一开始把六章全部移植。普通小程序的 web-view 能力及使用条件须在实际账号下确认，也不能把包一层网页视为默认可行的审核方案。

待核对的官方入口：

- [微信小程序 web-view](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)
- [微信小游戏运行环境适配](https://developers.weixin.qq.com/minigame/dev/guide/best-practice/adapter.html)
- [微信小游戏版本审核](https://developers.weixin.qq.com/minigame/introduction/guide/bbsh.html)

## 只在需要时增加的投入

- 第一阶段：已有静态托管、小范围试玩、修复问题；无须先租服务器或做账号系统。
- iOS 内测阶段：Xcode、真机和开发者会员；云同步可以后置。
- 微信阶段：完成主体／类目核对之后，才估算适配与运营成本。
- 商业化阶段：用户确实愿意继续玩后，再选择付费章节、广告或其他模式，并重新核对平台支付与资质要求。

## 内容与素材

六章的条约、史实和现实原型仍需单独做一次出处核验，本轮工程优化不代表已完成法律内容终审。默认开场使用程序绘制；可选的七段视频保留，现有播放界面有 AI 标识。视频编码或画面风格不足以证明作者和商业授权，发布前需要确认真实来源及许可。字体许可证随源码和离线打包保留。

当前没有新增采集或上传存档的功能。隐私政策仍须结合实际托管、后续 SDK、客服和数据流程编写，不能仅凭“本机存档”就断言整个服务完全不处理个人信息。
